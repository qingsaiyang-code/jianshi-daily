# 从 MVP 到持续更新

## 当前版本 v0.1

完成独立仓库骨架、知识流、分类 / 专区、演示归档、站内检索、浏览器偏好、分享与测试。先走通一次“修改 → 测试 → 提交 → PR → CI → 部署”，再增加需要账户、预算和外部数据的功能。

GitHub Actions 配置已经提供；只有推送到真实仓库后才会运行。Vercel 需要维护者导入仓库。本地验证与远程发布状态分别记录。

## v0.2：内容进入流程

建立 RSS / 开放 API 来源白名单，记录使用条款、速率限制、原始 URL、来源发布时间、抓取时间和内容指纹。限制响应大小与超时；以 URL 规范化和内容哈希去重。抓取器只处理允许的外部域名，不允许任意内网 URL。

先支持手动触发工作流，生成 draft JSON 和审查报告。过滤广告并不等于事实核验；未知来源、冲突证据或高风险内容进入待审核队列。文章正文按不可信数据处理，不执行其中的指令。

验收：重复运行不重复收录、一个来源失败不让整个批次丢失、正文与引用可追溯、草稿不直接混进已发布卡片。

## v0.3：AI 提炼与每日归档

服务端调用模型，将原文提炼为 200–300 字符中文摘要，输出受约束 JSON：稳定 ID、标题、摘要、要点、一级 / 二级类别、可选专区、引用。字符计数规则先固定，避免把 token 数误认为中文字符数。

核对来源是否直接支持结论；关键事实用独立证据交叉验证；保留生成模型、提示词版本与审核状态。健康、法律等领域不直接自动发布未经审查的个体建议。

先用 GitHub Actions `workflow_dispatch` 创建内容 PR，通过校验与人工审查后合并。稳定后再开启 `schedule`；例如北京时间每日 08:00 对应 `0 0 * * *`（UTC）。GitHub 定时执行可能延迟，不能当严格实时服务。

每日批次按 Asia/Shanghai 归档，以日期和内容指纹实现幂等；当天抓取失败保留旧库，明确记录失败，而不是把旧卡片标成新生成。需要无人审查的自动发布时，另开功能分支实现来源门槛、费用上限、失败重试、发布日志和回退策略，再有意识地启用。

验收：200–300 字符、来源有效、标签有效、批次可追踪、空批次不伪造内容、重跑不重复发文。现在没有部署这些功能，也没有配置定时任务。

## v0.4：实时联网问答

先检索站内卡片，再由服务端搜索适配器访问选定的联网提供商。答案必须带可打开的引用和抓取时间；前端区分站内命中、联网结果和暂时无法回答。允许用户明确触发联网，避免每次输入都产生费用。

搜索密钥仅在服务端；增加超时、速率限制、单日预算与缓存。公开限流需要共享存储或提供商限制，不能只靠无服务器实例的内存计数。外部网页不能改写系统提示；缺少可靠来源时不编造结论。

验收：站内命中和联网回退均可测试、真实引用、失败可恢复、密钥不出现在客户端包、预算能被限制。需要维护者选择提供商并配置自己的账户；不预设“永久免费”。

## v0.5：个人知识库

按实际需要增加账号、云端收藏、笔记、偏好与导入导出。把 server 数据适配层替换为托管数据库；迁移、权限和数据恢复都单独测试。保留本地游客模式，不为首个版本提前建设完整账号系统。
